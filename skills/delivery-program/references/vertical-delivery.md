# Vertical Delivery

Use this routine for one active slice inside a delivery program or for a standalone substantial slice.

## Bound The Slice

Define one observable behavior, its direct proof, exact write scope, existing seams, non-goals, hard limits, tripwires, approval gates, selected tests, commit expectation, and review owner.

When the work crosses domains, load or create the canonical assessment artifact. Keep unchanged runtime participants out of write scope.

Default to one implementor at exploratory and first-slice maturity. Add workers only when scopes are genuinely disjoint and the accepted envelope permits parallel work.

## Gate Expansion

Before edits, list every proposed new crate, store, protocol, service, background runtime, generalized abstraction, migration, and compatibility path.

For each expansion require current behavior it unblocks, evidence existing architecture cannot support that behavior, current consumers, a simpler alternative, and explicit authority.

Stop before implementing an unauthorized expansion.

## Implement

Pass the complete worker packet. Require workers to preserve the product proof and maturity envelope verbatim, stay within write scope, and report tripwire crossings rather than absorbing them.

Inspect returned work before integration. Reject unrelated changes and reconcile conflicting edits centrally.

## Prove

Run direct acceptance evidence first. Add broader validation only when policy, the changed surface, or current operational stakes require it.

Record the actual complexity delta and compare it with every tripwire. A passing test suite does not resolve a tripwire breach.

## Review

When the slice is embedded, leave review ownership to the parent program.

When standalone, run one initial integrated review and one bounded verification pass. Freeze finding identifiers after the initial pass. Verification may assess accepted findings and regressions caused by fixes, but may not introduce unrelated improvements.

## Finalize

Report behavior proved, maturity evidence, complexity delta, expansion decisions, changed files, validation, review result, commits or exception, unresolved risks, and worktree state.
